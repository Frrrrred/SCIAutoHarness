# Contributing

Use [GitHub Issues](https://github.com/Frrrrred/SCIAutoHarness/issues) for a reproducible problem or a focused proposal. Explain the expected behavior, actual behavior and relevant host, with sensitive paths and credentials removed.

Keep changes focused. Preserve documented command contracts, task identities, approvals, recovery semantics and source notices. Discuss changes to permissions, persistent formats or research evidence requirements before broadening their scope.

For a pull request, describe the concrete user behavior and compatibility impact. Follow the existing repository conventions and include the evidence needed to assess the change. Do not include private task records, credentials or local configuration.

See [architecture](docs/ARCHITECTURE.md), [compatibility](docs/COMPATIBILITY.md), [security](SECURITY.md) and [attribution](ATTRIBUTION.md).
