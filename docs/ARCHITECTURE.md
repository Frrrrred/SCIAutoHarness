# Architecture

[README](../README.md) · [Use](GETTING_STARTED.md) · [Compatibility](COMPATIBILITY.md)

SCIAutoHarness separates the reviewed task contract from execution records. The agent host reasons and performs authorized work; the local runtime binds the plan, original execution and acceptance evidence.

## Complete plan, selected context

The master states the objective, boundaries, dependencies and acceptance. Phase documents hold substantive methods and handoffs; shared protocols contain conditional rules. Recovery instructions identify the original entry and current context route. Complete human review covers the whole package. Execution loads only the selected phase, applicable protocols and accepted dependency summaries.

## Execution and acceptance

The host begins an approved stage, performs work and establishes its actual end before submitting original run facts. Acceptance checks artifacts and meaningful evidence; receipts and exit codes alone do not establish correctness. Source or evidence changes invalidate affected downstream results. Failed and inconclusive findings remain part of the task.

## Research work

Research plans connect questions to sources, identifiers, parameters, methods and outputs. Data and consequential choices are fixed before dependent analysis. Critical handoffs state actual checks, uncertainty and release decisions. The host uses relevant scientific tools without treating mechanical checks as scientific validity.

## Runtime and installation

The runtime and sole current skill entry live in `skills/sciautoharness`. Installation previews bind the source, exact targets and original identities. Safety format `5` retires recognized legacy directory trees outside skill discovery by same-volume rename and journals each confirmed change. Completed rollback restores those original trees; historical installation formats retain their own readers. Host settings and model credentials remain outside runtime authority.
