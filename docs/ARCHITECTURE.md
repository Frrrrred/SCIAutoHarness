# Architecture

[README](../README.md) · [Use](GETTING_STARTED.md) · [Compatibility](COMPATIBILITY.md)

SCIAutoHarness separates the reviewed task contract from execution records. The agent host reasons and performs authorized work; the local runtime binds the plan, original execution and acceptance evidence.

## Complete plan, selected context

The master states the objective, boundaries, dependencies and acceptance. Substantive phase documents hold methods and handoffs; shared protocols provide conditional rules. Recovery identifies the original entry and context route. Human review binds the complete package; execution loads the current phase, applicable protocols and accepted dependency summaries.

File-backed work reads master and recovery before deriving context. Approved session-only work inherits its full approved text and provenance without inventing a disk package. An infeasible or persistently blocked approach prompts whole-objective self-audit and, when needed, a complete replacement preserving original goals, constraints and execution facts. Material changes return to final-human review.

## Execution and acceptance

The host begins an approved stage, performs work and observes its actual end before submitting original facts. Spawned CLI close is process observation; explicit same-run business-end evidence remains the original controller's responsibility. Acceptance binds the receipt, required files, outputs, source versions and recursive dependency evidence.

Independent native delegates are read-only by default; the primary is the sole business writer and controller. A review snapshot identifies versions without supplying a semantic verdict. Receipts and exit zero do not establish correctness. Source or evidence changes invalidate affected results, while unrelated original work may still close factually. Failed and inconclusive findings remain recorded.

Changed closed pending, verified or stale work uses supported rework before repair. Administrative recovery preserves original facts without restoring approval. Active work stays with its original controller.

## Research work

Research plans connect questions to sources, identifiers, parameters, methods and outputs. Data and consequential choices are fixed before dependent analysis. Critical handoffs record actual checks, uncertainty and release decisions, including scientific failure modes beyond numerical gates. Mechanical checks do not establish scientific validity.

## Runtime and installation

The sole current skill entry and runtime live in skills/sciautoharness. Its 34-member inventory, record namespace and current entry-specific kinds define the package. Unsupported historical formats are preserved and refused, not silently converted.

Installation previews bind source and target bytes, ordinary single-link identity, managed instructions, configuration and metadata. Sensitive transaction storage is private before writes; original targets and parent protections remain bound. Complete installed transactions support validated normal rollback. Partial or unconfirmed activity retains its actual prefix and recovery evidence.

Host settings, credentials, model calls and permissions remain outside runtime authority. See [compatibility](COMPATIBILITY.md) for upgrade boundaries, platform coverage and the unresolved Windows replacement risk.
